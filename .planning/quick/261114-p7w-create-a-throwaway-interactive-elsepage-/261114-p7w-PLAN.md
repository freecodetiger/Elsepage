# Elsepage UI prototype exploration

Date: 2026-11-14. Branch: `ui/ux-modernization`.

The user explicitly requested a modern, refined, simple redesigned UI prototype and granted broad UI redesign latitude. Deliver an authorized throwaway visual spike, not SwiftUI implementation or a production design commitment. Preserve all earlier uncommitted work.

## Question and artifact

Which visual hierarchy best serves Elsepage's reading → reflection → personal thinking archive loop? Create one standalone HTML in `docs/prototypes`, with three structurally distinct variants selected by `?variant=A|B|C`, plus a shared switcher. An HTML artifact is appropriate because the production app is native iOS and has no web route to mount into.

## Directions

- A / 纸间 (recommended): warm paper, forest-green actions, editorial serif headings, a horizontal current-reading composition and small cover gallery.
- B / 清晰: neutral white/black, native-like typography, flat compact book rows and explicit reading progress; higher information density.
- C / 夜航: deep ink, restrained amber, centered current book and horizontal collection; focus on returning to reading.

All retain three actual tabs (书架 / 想法 / 我的), independent highlight/note surfaces and original Reflection text. Existing app remains source of truth; demo content, provider responses and all mutations live only in memory. No cloud sync, real API calls, journal-editing or unreachable Brain discussion presented as shipped features.

## Design decisions

Phone-sized viewing surface; calm/literary with restrained controls and comfortable 44px targets. Chinese system sans for controls and Songti/serif for selected titles, 4pt spacing rhythm, purposeful book-cover artwork authored for fictional demo books, real repository logo, subtle ≤240ms transitions and reduced-motion support. No remote fonts, dependencies, server, persistence or network calls.

## Delivery and verification

Implement bookshelf/search/sort/demo import, reader/chapter and appearance sheets, note/highlight, Reflection save into demo Thoughts, record detail and My/settings demo surfaces. Label fictional book/progress/AI text as demo data outside the app canvas. Verify rendering with html_preview at phone and wider widths; show the result using html_render. Check representative UI transitions without claiming native runtime equivalence. Leave app implementation and prior artifacts unchanged. No subagents needed for this bounded spike.
