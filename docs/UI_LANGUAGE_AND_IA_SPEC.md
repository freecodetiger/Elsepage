# 页外 UI 语言与信息架构规范

**状态：** Locked

**日期：** 2026-09-13

**范围：** iOS App 主界面语言、Tab、对象命名、页面层级、视觉语义 token

**不包含：** 数据模型改名、持久化迁移、Reader 排版引擎改造、完整国际化

**想法页详细规范：** `docs/THOUGHTS_UI_REDESIGN_SPEC.md`

---

## 1. 目标

页外的主界面应当让中文读者不需要理解工程术语，也能回答三个问题：

1. 我今天要做什么？
2. 我过去留下了什么？
3. 页外长期记住了什么，以及依据是什么？

实现原则：

- 主流程使用自然中文。
- 高级设置允许保留技术原文，但必须服务于可配置性，不进入日常阅读路径。
- 用户原始表达优先于系统派生信息。
- 细节按需展开，默认界面只呈现当前任务需要的信息。
- 视觉采用中性黑白体系；温度来自排版、留白、层级和动效，不来自全局品牌色。

---

## 2. 品牌锁定

### 2.1 用户可见品牌

**唯一用户可见品牌名：页外。**

要求：

- App 内主界面、通知、引导、错误和分享文案统一使用“页外”。
- 不再向用户显示 `ReadLoop`、`Elsepage` 或 `ElsePage`。
- `ReadLoop`、`Elsepage` 可以继续存在于仓库名、Target、Package、Database、Bundle ID、内部类型名和开发文档中。

### 2.2 Agent 称呼

- 日常叙述：使用“页外”称呼产品行为。
  - 例：`页外正在理解你的表达…`
  - 例：`页外记住了这一点。`
- 需要明确这是 AI 能力时：使用“AI 助手”。
  - 例：`问问 AI`
  - 例：`AI 回应`
- `Agent` 只允许出现在高级设置、诊断、开发文档和内部代码中。

---

## 3. Tab 锁定

主导航固定为四个 Tab，顺序如下：

| 顺序 | Tab | 职责 |
|---|---|---|
| 1 | 今天 | 当前阅读、补写记录、连续阅读与思考 |
| 2 | 书架 | 导入、查找、打开与继续阅读 |
| 3 | 想法 | 用户留下的阅读记录，以及按需展开的 AI 回应和依据 |
| 4 | 我的 | 长期形成的看法、问题、记忆与成就 |

禁止使用：

- `思想`：过于抽象，且无法区分原始记录与长期看法。
- `我的头脑`：口语上不自然，并强化“AI 读取大脑”的侵入感。
- `Memories`、`Thoughts`、`Questions` 作为一级栏目名。

---

## 4. 主要对象命名

每个对象只使用一个主名称。上下文可以自然改写，但不能重新引入冲突语义。

| 技术/领域对象 | 用户名称 | 说明 |
|---|---|---|
| Reflection | 阅读记录 | 用户在阅读后留下的原始表达；上下文可称“这次记录”“我的原话” |
| Thought | 看法 | 由多条阅读记录逐渐形成的、可演化的观点 |
| Question | 问题 | 尚未解决、值得继续追踪的问题 |
| Memory | 记忆 | AI 可长期依赖的用户信息，用户可确认、修改或忘记 |
| Journal | 这次留下 | 从一条阅读记录中整理出的可选结构化内容；不提供独立“档案”入口 |
| Reading Session | 这次阅读 | 时长、章节、高亮和笔记等阅读上下文 |
| Highlight | 高亮 | 原文高亮 |
| Note | 笔记 | 用户对原文的批注 |
| Reader Help | 问问 AI | 阅读中针对选区发起的临时答疑 |
| Agent Response | AI 回应 | 页外对用户表达或问题的回复 |

关键区分：

- `阅读记录` 是用户说了什么。
- `看法` 是页外整理后，用户未来仍可能修改的长期观点。
- `记忆` 是用户允许页外长期依赖的信息。
- 三者不得互相替代使用。

---

## 5. 主流程术语映射

主流程不得使用未解释的工程词。推荐映射如下：

| 当前词 | 主流程文案 | 高级设置 |
|---|---|---|
| Reflection | 阅读记录、这次记录 | 保留 Reflection |
| Agent | 页外、AI 助手 | 保留 Agent |
| Memory | 记忆 | 保留 Memory |
| Thoughts | 正在形成的看法 | 保留 Thought |
| Questions | 还在想的问题 | 保留 Question |
| Provider | AI 服务 | 保留 Provider |
| API Key | 密钥、API 密钥 | 保留 API Key |
| Base URL | 接口地址 | 保留 Base URL |
| Embedding | 语义索引 | `Embedding（语义索引）` |
| Reranker | 结果精排 | `Reranker（结果精排）` |
| RAG | 书内检索 | `RAG（书内检索）` |
| EPUB | EPUB | EPUB |
| AI | AI | AI |

高级设置采用“技术原文（中文解释）”格式，例如：

- `Embedding（语义索引）`
- `Reranker（结果精排）`
- `RAG（书内检索）`

不得在按钮、空状态、错误提示和引导页面中只显示技术缩写。

## 6. 想法页信息架构

详细规范以 `docs/THOUGHTS_UI_REDESIGN_SPEC.md` 为准。

锁定高层规则：

- 想法页只有一个主信息流。
- 不提供“档案”入口、`记录 / 档案` 分段控件或档案筛选。
- 折叠卡片只显示书名、中文日期和自动概要。
- 不显示“有回应”“请 AI 回应”“有关联”或讨论次数。
- 所有 Reflection 默认自动进入 AI 回应流程，不要求用户手动发起。
- 概要由第一次阅读记录和第一次 AI 回应自动生成，成功后永久固定。
- 点击卡片进入独立详情页，依次显示概要、我的原话、AI 回应、每条回应下的轻量依据脚注、可选的“这次留下”和对话输入。
- 时间/书籍只作为分组方式，不与内容类型并列。

## 7. 我的页信息架构

“我的”页不是数据库管理器，也不是第二个阅读记录列表。

固定顺序：

1. 正在形成的看法
2. 还在想的问题
3. AI 记住的我
4. 成就

要求：

- 成就不得置于页面顶部。
- 每个分区只显示当前最重要的内容，不显示内部字段名。
- 没有内容时用一句话说明它会如何形成，不展示空卡片。
- 证据、置信度、来源和完整操作放在详情或展开态中。
- 记忆操作使用用户语言：`准确`、`不准确`、`修改`、`忘记`。

## 8. 视觉语义与 Token

### 8.1 原则

- 应用壳层：中性黑白。
- 阅读内容：保留独立纸张白、暖色和深色主题。
- 品牌色、交互色、状态色必须拆开。
- 一个颜色不得同时承担品牌、按钮、进度和成功状态。

### 8.2 Token 角色

| Token 角色 | 用途 |
|---|---|
| background | 页面底色 |
| surface | 卡片、表单、导航表面 |
| surfaceSecondary | 卡片内的次级内容表面 |
| border | 分隔线和轮廓 |
| contentPrimary | 主文本 |
| contentSecondary | 次级文本 |
| contentTertiary | 辅助文本和占位 |
| brand | 产品识别、选中态、强调内容 |
| interactive | 可点击控件、链接、主要按钮 |
| onInteractive | 交互色之上的文字和图标 |
| success | 已完成、连接成功、索引就绪 |
| warning | 需要注意但不失败的状态 |
| danger | 删除、失败、录音中 |
| readerPaper / readerSepia / readerDark | 阅读器独立主题 |

### 8.3 黑白目标色

| Token | Light | Dark |
|---|---|---|
| background | `#F2F2F2` | `#0B0B0B` |
| surface | `#FFFFFF` | `#181818` |
| surfaceSecondary | `#F7F7F7` | `#222222` |
| border | `#D4D4D4` | `#343434` |
| contentPrimary | `#111111` | `#F4F4F4` |
| contentSecondary | `#666666` | `#A6A6A6` |
| brand | `#111111` | `#F5F5F5` |
| interactive | `#111111` | `#F5F5F5` |
| onInteractive | `#FFFFFF` | `#111111` |
| success | `#237A3B` | `#70D88B` |
| warning | `#8A5A00` | `#F0B44D` |
| danger | `#B42318` | `#FF7A70` |

要求：

- 正文与交互文本满足 WCAG AA 4.5:1。
- 状态色只在状态语境使用。
- 边框和分隔线不得依赖颜色区分唯一含义。
- 深色模式使用炭黑，不使用橄榄绿黑。

---

## 9. 字号与层级

- App UI 默认使用系统无衬线字体。
- 衬线字体保留给书名、阅读内容和少量编辑感标题。
- 正文优先使用 `.body`、`.subheadline` 和动态字体。
- 不通过缩小到 `.caption2` 来塞入更多信息。
- 信息过多时先删除或延后展示，而不是降低字号。

---

## 10. 迁移规则

实施按以下顺序：

1. 锁定本 spec。
2. 更新 PRD §10.1，记录从“暖色品牌体系”到“中性黑白体系”的产品偏差。
3. 拆分并更新设计 token 与无障碍测试。
4. 替换主流程术语与品牌名。
5. 重构“想法”页。
6. 重构“我的”页。
7. 只做构建、测试和用户真机验收，不新增持久化迁移。

---

## 11. 验收标准

- 主导航只有：今天、书架、想法、我的。
- 主流程中不再出现未解释的 `Reflection`、`Agent`、`Provider`、`RAG`、`Embedding` 和 `Reranker`。
- `ReadLoop` 和 `ElsePage` 不再出现在用户界面。
- “想法”页默认只呈现一个清晰的主信息流。
- 时间/书籍成为分组方式，不再和内容类型并列。
- “我的”页顺序固定，成就位于底部，详情按需展开。
- 应用壳层在亮色和深色下均为中性黑白。
- 阅读器的纸张、暖色和深色主题不受应用壳层配色影响。
- 设计 token 测试覆盖正文对比度、主按钮对比度和状态色对比度。
