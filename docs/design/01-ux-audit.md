## 2. 总体判断

### 2.1 已经成立的优点

1. **三个根页面的视觉语言已经统一**：16pt 页边距、系统字级、单一语义色、无逐行卡片；相比上一版明显减少了“demo 味”。
2. **书架的首屏层级是对的**：当前书在上、全部书籍在下；当前书行是唯一的大封面；网格只保留封面、书名、作者。
3. **我的页的信息架构修复有效**：看法/问题/记忆成为并列分段，顶部固定，任何一类变长不会把其他类推走；连续天数已移除。
4. **底部原生玻璃分体栏本身成立**：左侧三 Tab 是真 `UITabBar`（系统玻璃与选中透镜），右侧加号只在书架出现；加号隐藏时玻璃胶囊 frame 不移动（`x=8, y=749, width=318, height=83` 的实测结论仍成立）。
5. **AI 与用户内容的区分是产品级优点**：用户原文、AI 回应、AI 优化版、AI 推断/用户明确表达都有可见标签；引用有上标与来源列表。
6. **本地优先的语言是具体的**：保存先落本机、无 Key 仍可读、引用可回原文（书籍证据）、删除有确认或撤销的局部机制。

### 2.2 十二维评分

| 维度 | 评级 | 一句话结论 |
| --- | --- | --- |
| Discoverability | 部分 | 搜索、加号、标题动作清楚；阅读器底部动作被遮挡，书库缺少“上次读到哪”的线索，“继续想想”是死按钮。 |

## 3. 按启发式展开

### 3.1 Discoverability

**成立的部分**：书架搜索在标题下方、加号在底部右侧、我的页成就与设置都在标题行右侧；阅读器选中文字后出现“笔记 / 问 / 复制”，比藏在菜单里好。

**主要缺口**：

- 阅读器一旦显示控制栏，底部“目录 / 标注 / 读到这里 / 进度”被自定义玻璃栏盖住（V，UX-001）。用户看不到，也点不到。
- 书架网格不再显示进度或最近阅读；排序入口已移除（V，UX-006）。用户只能靠封面记忆或搜索书名/作者找回旧书。
- “继续想想”在看法/问题详情工具栏可见，但点击没有 Sheet（R，UX-004）。`discussingBinding` 只定义未使用，`BrainDiscussionSheet` 没有 `.sheet` 消费者。
- “问 AI”在未配置 Provider 时仍可触发，失败后只有一行错误文字，没有“去设置”的入口（R，UX-007；上一轮运行曾观察到同类错误）。
- 图标 Tab 没有文字标签（V，UX-025）；首次使用需要把“灯泡”映射到“想法”、“人像”映射到“我的”。

### 3.2 Learnability

首启是一个清楚的三步流程：导入 → 连 AI（可跳过）→ 第一次阅读。文案把“无 Key 也能读”讲清楚了，这是优点。

学习成本集中在三处：

- **BYOK 表单**：OpenAI 预设下“模型”为空，用户必须知道并手填模型 ID；“测试连接”在空表单上仍可点（V，UX-016）。对不熟悉 API 的读者，这是首启最大的认知门槛。
- **术语**：“想法”Tab 实际是阅读记录；“我的”里的“看法”才是 Brain 中的 Thought；还有“问题”“记忆”。四个词没有在界面里定义（H，UX-021）。这不是代码缺陷，但需要用户测试确认是否真的混淆。
- **“今天先不了”**：文案听起来是“今天不写，改天再写”，实际会把该 session 永久加入 dismissal 列表，且没有手动补写入口（V/R，UX-002）。这是语义学习最危险的一处。

### 3.3 Navigation

根级导航是清楚的：三个 Tab 各自 `NavigationStack`，根页面隐藏系统导航栏，用自定义标题行。问题出在**导航容器的所有权**：

- 自定义底栏挂在 `TabView` 的 `safeAreaInset(edge: .bottom)` 上（`AppShell.swift:49-53`）。它不属于某个 Tab，也不会被 `ReaderScreen` 的 `.toolbar(.hidden, for: .tabBar)` 隐藏（`ReaderScreen.swift:61-62` 只隐藏系统 tab bar）。
- 因此从书架 push 进入阅读器时，底栏仍在；从想法/我的用 `fullScreenCover` 打开阅读器时，底栏不在。同一个 `ReaderScreen` 有两种 chrome 结果（V，UX-001）。
- 阅读器顶部左侧是“读到这里并返回”（`ReaderScreen.swift:164-166`），视觉上却只是一个返回箭头；它结束会话，还可能弹出反思。底部原本还有一个“读到这里”，但被盖住（V，UX-009 + UX-001）。
- 补写想法只针对 `LibraryModel.currentBook` 解析（`LibraryNextActionModel.swift:28-46`）。如果用户结束 A 的阅读后打开 B，A 的待补写入口不会出现在任何地方，除非 A 再次成为 current（R，UX-022）。

### 3.4 Information Architecture

三个根 Tab 的分工是：书架（书）、想法（记录）、我的（长期形成的内容）。这个分工成立；“我的”内部改成三段并列，是这一轮最正确的 IA 决策。

仍然存在的结构问题：

- **“想法”与“看法”不是同一层概念，却像同义词**。想法 Tab 是 Reflection 记录；我的里的看法是 Brain Thought。用户想“回看我的想法”时，不知道去哪个 Tab（H，UX-021）。
- **书库没有“阅读状态”层**。网格只有封面、书名、作者；没有在读、未读、已读、进度、最近阅读。当前书行只覆盖一本。对于 10 本以上的书库，“找一本以前读过的书”变成记忆任务（V/H，UX-006）。
- **反思记录没有手动创建入口**。正常路径只有结束会话或书架补写；一旦 dismissal，用户无法从想法页新建一条（V/R，UX-002）。
- **成就从主页移走是对的**，但成就页与根页面的返回、背景、底部栏没有统一（V，UX-026）。

### 3.5 Cognitive Load

根页面已经明显减负：没有统计卡、没有连续天数、没有逐行卡片。阅读器却仍是高负荷区域：

- 顶部 chrome 同时有返回、书名/章节、搜索、格式；底部有目录、标注、读到这里、进度。控制栏出现时，章节标题被顶部 chrome 遮住（V，UX-011）。
- 阅读器搜索 Sheet 是 medium detent，底部自定义栏透过半透明材质显示出来，形成第二层“底栏”（V，UX-001）。
- 反思编辑 Sheet 顶部三个大胶囊（今天先不了 / 标题 / 保存），保存不可用但不说原因；编辑区是一大片空白，只有一行占位符（V，UX-019）。
- 设置里的 Embedding / Reranker 是技术词；RAG 行的说明文字被渲染成绿色成功态（V，UX-015）。

### 3.6 Visual Hierarchy

书架的首屏层级是当前做得最好的：34 标题 → 搜索 → 当前书 → 全部书籍。问题在细节：

- 当前书标题 `lineLimit(1)`（`LibraryView.swift:266-269`），在约 230pt 文本列里 “ReadLoop Foundation Fixture” 被截成 “ReadLoop Foundatio…”。行高固定 180pt，右侧和下方都有大量空白，信息却先被截断（V，UX-012）。
- 补写胶囊是 `ZStack` 的 bottomTrailing overlay，视觉上悬在空白里；如果进度存在，它与进度条/百分比的右下区域存在重叠风险（R，UX-012）。它只有 34pt（`.controlSize(.regular)`），低于 44pt 触达标准；设计文档写的是“命中区域补到 44”，当前代码没有补（V/R，UX-027）。
- 我的详情页仍是 20pt 页边距、19/13 自定义字号、胶囊状态和灰底卡片；从新的根页面进入会感觉换了一个 App（V，UX-020）。
- RAG 的说明文字用绿色，绿色在这里代表“正常/成功”而不是“状态描述”，会让人误以为索引已健康（V，UX-015）。

### 3.7 Consistency

- **同类删除不同策略**：删书有确认；删记忆里的“忘记”立即硬删除；删整条记录藏在长按菜单里且有确认；删高亮有 5 秒撤销。用户无法形成“删除会发生什么”的稳定预期（R，UX-008/024）。
- **同类“保存”不同策略**：聊天气泡自动保存；反思需要显式“保存”；笔记自动保存；Provider 需要“保存配置”再“测试连接”。每种都有理由，但界面上没有统一的保存模型提示（V/R，UX-016）。
- **阅读器两种入口不同 chrome**：push 有自定义底栏，fullScreenCover 没有（V，UX-001）。
- **详情页两套视觉系统**：根页面 16pt/12pt 圆角；想法详情/我的详情用 20pt/自定义字号/胶囊（V，UX-020）。
- **Sheet 手势不一致**：阅读器 Help Sheet 显示 drag indicator，却设置 `interactiveDismissDisabled(true)`；补写想法 Sheet 可以下滑关闭，而下滑等于永久放弃（V/R，UX-018/002）。

### 3.8 Feedback

做得好的：复制/删除有底部短暂胶囊；删除高亮/笔记可撤销；保存笔记有“已保存到标注”；反思保存有状态切换；高亮菜单有选中勾；触感反馈克制。

反馈缺口：

- 阅读器底部动作被盖住，等于没有可见反馈（V，UX-001）。
- 追问的 pending 气泡在 `.sending` 状态显示“已发送”（`SessionReflectionSheet.swift:1412-1416`），但此时还没有落库成功（R，UX-017）。
- 点“过去 · 你的想法”来源，Sheet 会缩到 184pt，但没有跳转；因为旧反思证据的 `locator` 是 `nil`（`ContextAssembler.swift:102-103`），`jumpToCitation` 直接 return（`ReaderScreen.swift:278-282`）。用户得到的是“点了一下，什么都没发生”（R，UX-013）。
- 点“继续想想”没有 Sheet，没有任何反馈（R，UX-004）。
- 设置里 RAG 行永远是绿色，绿色不再意味着成功（V，UX-015）。
- AI 回应过程中没有 Stop；`isResponding` 只禁用发送（R，UX-017）。

### 3.9 Error Recovery

- **补写想法**：`今天先不了` 会 dismiss，`LibraryView.onChange` 随后 `dismissReflectionPrompt`，把 sessionID 写入 UserDefaults（最多 50 条），resolver 永久排除；同时未提交的草稿没有持久化（`SessionReflectionSheet.swift:1127-1129`、`LibraryView.swift:81-89`、`TodayProductState.swift:18-74`）。用户以为“改天”，实际是“这次永远不写”；如果已经输入文字，文字也一起消失（V/R，UX-002）。
- **删书**：确认文案只说“会删除本机 EPUB、阅读位置和全部标注”，但数据库外键从 `books` 级联到 `readingSessions`、`reflections`、`highlights`、`notes` 等（`AppDatabase.swift:49-105`）。用户可能为了清理文件而删书，连带失去反思与对话（V/R，UX-003）。
- **忘记记忆**：直接 `model.delete`，硬删除，无确认、无撤销（`MyMindView.swift:602-620`、`MyMindModel.swift:138-140`）（R，UX-008）。
- **AI 未配置**：错误只显示“还没有配置可用的模型服务”，没有按钮去设置（`ReaderHelpModel.swift:340-366`）（R，UX-007）。
- **启动失败**：`ContentUnavailableView` 没有重试/修复入口（R，UX-023）。
- **反思/追问失败**：原文保留、可重试，这是好的；但没有 Stop，长请求只能等或离开（R，UX-017）。

### 3.10 Accessibility

**成立**：大部分图标按钮有 44pt；标题有 header trait；封面有替代标签；动态字体下网格退化为一列；Reduce Motion / Reduce Transparency 有分支；深色模式实测一致；AX 标签整体完整。

**不成立**：

- 辅助功能大字号（accessibility-extra-large）下，`ElsepageSearchField` 固定 36pt 高（`ElsepageComponents.swift:199-235`），占位文字溢出输入框；当前书行固定 180pt、标题/作者 `lineLimit(1)`，只剩碎片（V，UX-005）。
- 补写胶囊 34pt，清除搜索按钮 16pt，均低于 44pt（V/R，UX-027）。
- 图标 Tab 无可见文字；VoiceOver 有标签，但视觉学习成本仍在（V，UX-025）。
- AX 树在设置页与反思页的“默认保存录音/保存音频”旁额外暴露了一个无名 `switch "1"`（V，AX 观察）。这可能是 XCTest/AX 快照的伪影，也可能是真实的重复元素；未做 VoiceOver 复验，因此只记为待验证，不列为正式缺陷。
- 未做 VoiceOver 全流程、Reduce Motion 全流程、iPad/横屏、真机 Dynamic Type 验证。

### 3.11 Efficiency

- 高频任务“继续读当前书”只有一步，做得好。
- “找一本以前读过的书”没有排序/筛选/进度，只有搜索；搜索又只匹配书名/作者（V，UX-006）。
- “问 AI”在未配置时没有就近修复路径，必须退出阅读器 → 书架/我的 → 设置 → 聊天模型（R，UX-007）。
- BYOK 首次配置要手填模型 ID，空表单也能测试，失败后再猜（V，UX-016）。
- 反思保存后自动请求回应，减少一次点击；但等待期间没有 Stop，失败后需要重新进入（R，UX-017）。

### 3.12 Perceived Quality

视觉上，三个根页面已经接近“成熟 iOS 产品”；但成熟感被以下细节拉回：

- 阅读器底栏压住阅读器控件（P0）。
- 一个可见的“继续想想”按钮完全不工作（P1）。
- 当前书标题被截断、补写胶囊悬空、封面占位字断行（P2）。
- RAG 绿色状态、详情页旧视觉、成就页返回按钮样式不统一（P2/P3）。
- 反思 Sheet 的“今天先不了”与“保存”同等显眼，且保存不可用没有解释（P2）。

## 4. 产品特性专项判断

| 问题 | 判断 | 证据 |
| --- | --- | --- |
| 阅读界面是否足够安静？ | **否**。阅读器内仍显示 App 底部玻璃栏与加号；显示控制栏时底部阅读控件被遮挡；搜索 Sheet 下还能看到底栏透出。 | V，UX-001/011 |
| AI 功能是否打扰阅读？ | **基本不打扰**。AI 只在用户选中文字后主动点“问”才出现，没有自动弹窗、没有常驻 AI 入口。 | V，UX-007 只涉及失败路径 |
| 选区、批注与阅读能否自然衔接？ | **大体可以**。4 色 + 笔记 + 问 + 复制是单层工具；笔记预览/编辑、自动保存、清空删除 + 撤销都有。问题是笔记 Sheet 头部元素偏多，且底部阅读控件被盖住时“标注”入口不可达。 | V/R，UX-001/019 |
| 提问过程中能否保留阅读上下文？ | **可以**。Help Sheet 保留选中原文、章节、会话线程；点引用缩到 184pt 露出正文；关闭即丢弃是明确的产品选择。 | V/R，UX-018 |
| 证据引用是否清晰、可信、可回跳？ | **书籍证据可以；过去反思不可以**。上标 + 来源列表清楚；书籍段落有 locator 可跳；过去的想法 `locator: nil`，点来源只会缩 Sheet，不会跳转，也不说明原因。 | R，UX-013 |
| 防剧透边界能否被用户理解？ | **不能**。界面没有在提问前说明“只使用你读到的内容”；只有失败降级时出现“仅基于当前可见文本回答，未检索后文”，或回答后的“基于已读内容”。用户无法预判边界。 | R，UX-014 |
| 用户能否区分本地内容与 AI 生成内容？ | **能**。用户原文、AI 回应、AI 优化版、AI 推断/用户明确表达、出处标签都在视觉上分开；这是应保留的产品资产。 | V |
| 思考记录是否形成自然闭环？ | **有闭环骨架，但入口会断**。结束会话 → 反思 → AI 回应 → 想法/我的 的路径存在；但“今天先不了”会永久关闭这次补写，待补写只对当前书可见，“继续想想”不可用。 | V/R，UX-002/004/022 |

## 5. 视觉与交互细节

| 项目 | 观察 | 判断 |
| --- | --- | --- |
| 排版与字重 | 根页面使用 34/22/20/17/15/13 系统字级；阅读器/引导保留衬线编辑感。 | 方向成立；当前书名 22/600 单行截断，细节未收口 |
| 内容密度 | 书架/想法/我的已减负；阅读器 chrome 与反思 Sheet 仍偏密。 | 根页面好，深层页面未同步 |
| 页面留白 | 书架单书时大量空白是内容驱动，不是缺陷；当前书行内部空白分配不合理（标题截断但下方空）。 | 局部问题 |
| 颜色与对比度 | 语义色统一；深色模式实测正常；对比度有既有测试。RAG 绿色是语义误用。 | 基本成立，个别语义错误 |
| 控件层级 | 标题行动作、搜索、当前书、网格层级清楚；反思 Sheet 的主次动作不清楚。 | 部分 |
| 图标含义 | 齿轮/勋章/加号清楚；灯泡/人像无文字；阅读器“格式”是本地化字形，尚可。 | 图标 Tab 需学习 |

## 6. 结论

ElsePage 现在的主要差距**不是审美**。三个根页面的视觉语言已经足以支撑“现代、安静、原生”的定位；真正的差距是**交互状态的所有权与可恢复性**：

1. 自定义 shell 的底栏没有和全屏阅读器建立边界，导致 P0 级遮挡与两套阅读器 chrome。
2. 破坏性/放弃性操作没有把真实后果说清楚：补写“今天先不了”永久关闭、删书连带反思、忘记记忆不可撤销。
3. 书库无法回答“我上次读到哪、哪本读过”，多书场景下找回旧书的成本过高。
4. 辅助功能大字号是硬伤，不是打磨项。
5. 差异化功能“继续想想”有可见入口但没有消费者，AI 失败路径没有就近修复。

这些问题都可以在不改变产品方向的前提下修复；完整分级、优先级和建议方向见 [优先问题清单](01-prioritized-issues.md)，逐场景走查见 [用户旅程分析](01-user-journey-analysis.md)。
