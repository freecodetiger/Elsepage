# ElsePage 优先问题清单

2026-11-15。评估对象与证据口径见 [UI/UX 启发式评估](01-ux-audit.md) 与 [用户旅程分析](01-user-journey-analysis.md)。本清单最初只排序、不实现；同日已按 P0 → P1 → P2 修复部分问题，逐条状态见 [§10 修复记录](#10-修复记录2026-11-15)。

## 0. 阅读方式

- **严重程度**：P0 阻断核心任务或严重误操作；P1 明显损害核心体验；P2 可用性/一致性问题；P3 细节打磨。
- **修复优先级**：立即（本轮收口）/ 下一轮 / 后续。
- **证据等级**：V 已运行观察或确定 UI 路径；R 源码确定但当前样本不足；H 需要用户测试。
- 每条问题都给出复现、证据、原则、影响与方向；跨文档引用同一 ID。

## 7. 最值得重新设计的 3 个用户流程

### 7.1 阅读器的 chrome 所有权与退出语义（UX-001 / UX-009 / UX-011 / UX-018）

**现在**：shell 的底栏拥有底部空间；Reader 的 chrome 叠加在它上面；退出同时是结束会话；Sheet 手势不一致。

**重新设计的目标**：进入阅读器后，**Reader 拥有整块屏幕**；顶部与底部 chrome 都由 Reader 控制，且互不遮挡；退出只有一个清晰语义（结束阅读/返回书架），并在需要时解释后果；阅读器内所有 Sheet 不再透出 shell 元素。

**成功标准**：阅读器内 AX 树没有 shelf tab bar；底部三个动作完整可点；chrome 是临时浮层，隐藏后正文完整、章节起始页标题完整；从 push 与 fullScreenCover 进入的 Reader chrome 完全一致。

### 7.2 反思捕获与放弃（UX-002 / UX-019 / UX-022）

**现在**：写/不写是一个 Sheet；跳过文案温柔但行为永久；待补写只对当前书；没有手动新建。

**重新设计的目标**：把“写一点”当成一个有状态的草稿：可稍后、可恢复、可明确放弃；待补写是一个跨书的轻量收件箱，而不是当前书行的 overlay；放弃必须说清“这次不会再提醒”。

**成功标准**：关闭 Sheet 后草稿可恢复；跳过有明确确认；多书待补写可见；用户能在想法页手动新建一条反思。

### 7.3 多书书架的找回模型（UX-006 / UX-012 / UX-028）

**现在**：一本书的“当前行” + 无状态的网格；排序入口移除；新导入与上次阅读混在一起。

**重新设计的目标**：书架回答三个问题：**上次读的是哪本、每本读到哪、怎么按最近/书名/作者找回**。不恢复每格三行小字；用一条元信息、一个排序/筛选入口和一个明确的“新导入”状态完成。

**成功标准**：10 本书的可用性测试中，用户能在 10 秒内找回一本两周前读过的书；当前书行的书名完整可读；新导入书不会被误认为上次阅读。

## 8. 最有价值的 1 个样板页面

**书架**。

理由：

- 它已经体现了本轮最成熟的视觉系统：16pt 页边距、34/22/20/17/15/13 字级、单一语义色、封面承担颜色、无逐行卡片。
- 它的层级（标题 + 搜索 + 当前书 + 全部书籍）可以直接复用到想法/我的详情页，作为“根级列表”的样板。
- 它同时暴露了本轮最关键的三个系统问题：当前书模型（UX-028）、多书找回（UX-006）、当前行排版（UX-012）。把书架做对，等于把“书的入口”做对；其余页面可以沿用它的 spacing/typography/empty-state 规则。

**样板化的内容**：16pt 页边距；标题行与 44pt 玻璃胶囊；搜索字段（但需修复大字号）；当前书行（两行标题、明确状态、胶囊与进度不重叠）；三列网格 + 一条轻量元信息；空态/搜索空态；深色模式；Dynamic Type 的纵向退化。不要样板化的是：当前书行的 180pt 固定高度与单行标题。

## 9. 最终结论

**ElsePage 距离成熟、现代、高质量 iOS 产品，最主要的差距不是视觉审美，而是交互状态的所有权与可恢复性。**

具体证据：

1. **视觉已经统一，边界没有统一**。三个根页面已经有一致的字级、间距和色彩；但自定义底栏是 shell 级 `safeAreaInset`，会进入阅读器和阅读器 Sheet，直接遮挡阅读控件（UX-001）。这不是“阅读器没优化”，而是新 shell 没有定义“谁拥有全屏阅读”。
2. **破坏性/放弃性操作没有把后果说清楚**。“今天先不了”永久关闭补写并丢草稿（UX-002）；删书文案漏掉反思与会话（UX-003）；“忘记”记忆立即硬删除（UX-008）。这三处都直接损失用户资产，且都没有与“删除高亮可撤销”同级的恢复机制。
3. **书库不能回答老读者的问题**。网格没有进度/最近阅读，排序入口被移除，搜索只匹配书名/作者（UX-006）；当前书还可能是一本刚导入未打开的书（UX-028）。对一个“读 → 反思 → 回看”的产品，这意味着第二次使用就找不到上次的入口。
4. **无障碍大字号是硬伤，不是打磨项**。固定 36pt 搜索框和 180pt/单行当前书行在 accessibility-extra-large 下直接破版（UX-005）。
5. **差异化能力有入口没有闭环**。“继续想想”是死按钮（UX-004）；过去反思引用是死链接（UX-013）；AI 未配置时是死路（UX-007）。这些不是视觉问题，而是产品承诺没有兑现。

因此，下一步不应该继续加视觉细节，而应该先收口三条边界：**shell 与阅读器的边界、放弃与删除的边界、当前书与其他书的边界**。这三条边界修好后，现有的 16pt/系统字级/单一语义色视觉语言才真正具备“成熟产品”的说服力。
