# 字号与版式：三组重做方案

2026-11-14。用户认为 A 减字版的字体、间距和整体比例仍显得细碎，要求新的方案。本轮重新探索字号层级与空间组织，不继续沿用原 A 的小号衬线界面字与三列书架。旧原型保留作历史对照，未修改 App。

[打开同内容版式对比](../prototypes/elsepage-layout-studies.html)。单个离线 HTML，可直接打开；底部左右切换，桌面右侧可直接选择，URL `?variant=1|2|3` 固定方案。按完整手机逻辑尺寸展示，不把三部手机缩成细小缩略图。全部书目、段落、进度和记录均为演示数据。

## 共同的排版基线

- 采用面向 iOS 的系统无衬线字体栈，标题和正文通过尺寸、字重、行高形成层级；不再让大量浅灰小字承担主要信息。
- 页面标题36–40，当前书名26–30，区块标题20，正文与操作17，作者/章节等14–16。底部导航标签12、系统时间15。数值是此HTML的CSS逻辑像素参考，不是原生Dynamic Type验收结论。
- 页边距24，组件间隔24/32为主；主要按钮高52，图标按钮至少46。手机窄宽下保留大字号，仅小幅调整边距和封面宽度。
- 首屏内容按重要程度呈现，其余自然滚动；不为多放一排书而压小文字。搜索入口移入顶栏，按需展开，给阅读区域腾出稳定空间。
- 持续保留继续阅读/补写想法两条可见去向，数据与交互目的保持相同，以便公平比较版式。

## 方案取舍

| 方案 | 布局与阅读顺序 | 字级参考（标题/当前书/正文/辅助） | 适合与代价 |
| --- | --- | --- | --- |
| 1 原生大字 · 推荐先看 | 横向当前阅读 → 两项操作 → 双列封面；无额外卡片包裹当前书 | 36 / 26 / 17 / 14–16 | 接近成熟iOS产品的使用秩序，兼顾书籍和下一步操作；较大封面降低了同屏藏书数量 |
| 2 编辑目录 | 无独立阅读卡片；书目在同一基线纵向展开，用大书名、明确分隔和间距区分 | 40 / 30 / 17 / 14–16 | 更有编辑感，扫书名直接；封面占比降低，按钮边角更利落 |
| 3 封面主导 | 当前书置于完整封面区域，标题/作者/进度居中；操作在其下，其他书横向排列 | 36 / 28 / 17 / 14–16 | 专注当前阅读，封面更有表现力；其他藏书的首屏可见性较低 |

建议先比较1和2：1更适合作为整体App的稳定基础，2可提供更鲜明的书目秩序；3用于判断是否希望首页更偏沉浸和单书聚焦。当前没有用户选中方案。

## 原型覆盖与边界

版式切换、键盘左右切换、搜索/无结果、排序、打开演示正文、Reflection Sheet与非空原话保存、想法/我的演示页面可体验。保存只留在当前页面内存，书籍归属随记录保存；无真实Provider、读书文件、数据库、云同步或录音。重点是对照排版和触达尺寸，未补全旧原型中的全部批注/RAG路径。

本轮没有制作正式组件库，也没有原生字号、VoiceOver、键盘避让或长书性能验收。大字号不是随意整体放大：封面比例、列数、标题占位、按钮高度、信息顺序同步调整。最终转为SwiftUI时仍需用语义字体、动态字号与具体内容重新校验。
