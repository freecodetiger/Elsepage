# 我的：把并列的内容做成并列

2026-11-14。书架和想法/阅读收敛后，用户指出“我的”页把不同性质的内容垂直堆叠，主次不清；上方内容一多，下方就被推走。同时，连续阅读/思考天数不应当作主页指标。本轮重做“我的”的信息架构；“想法”和“阅读”保留上一轮结果。

> 2026-11-15：通用 tokens 与可复用组件以 [Design System Guide](04-design-system-guide.md) 为准；本页保留页面级字号、密度与容器规格，不重复定义组件 API。
>
> 2026-11-15：阅读器已按 [阅读体验重构报告](05-reader-redesign-report.md) 落地；本页“阅读”一节保留为目标视觉规格，实际 chrome、选区与问答状态以重构报告为准。

[打开静态样张](../prototypes/elsepage-native-screens.html)。单文件、无 JavaScript、无网络请求；三帧 393×852，内容均为演示数据。

## 诊断

“我的”里有三类东西：正在形成的看法、还在想的问题、AI 记住的我。它们性质不同：

- 看法和问题是用户自己的思考，点开继续讨论；
- 记忆是 AI 对用户的理解，点开展开来源与纠正操作；
- 成就不是同一层的内容，是奖励记录。

把它们竖着排成一条 feed，会得到三个问题：

1. 从上到下读，第一段自动成为“主要”，后面的自动成为“次要”，但这不是设计决定的主次，只是排序结果。
2. 任何一类变长，都会把后面几类推得更远；内容越多，越需要长滚动才能看到别的类型。
3. 三类内容有不同的操作方式，却在同一个流里共用同一种行；层级和交互都被抹平。

这不是靠加间距、换卡片能解决的，是信息架构问题。

## 三个方案

| 方案 | 结果 | 取舍 |
| --- | --- | --- |
| 继续垂直分区 | 现状 | 需要长滚动；主次由内容长度决定，否决 |
| 目录式入口：看法 / 问题 / 记忆 各一行，进入独立列表 | 层级最稳定，也最易扩展 | 为三个只有几条的列表增加三个页面和一层导航，重 |
| 系统分段控件 + 单一列表 | 三类并列；顶部固定；一个页面 | 采用。用 `Picker(.segmented)`，不新增自绘组件 |

分段控件是这里最小的“并列”表达：顶部固定，选中哪一类就只显示哪一类；任何一类变长只会在自己的列表里滚动，不会把其他类型推走。段标题带数量（看法 3 / 问题 2 / 记忆 3），一眼能看到三类内容的整体形状，而不需要再加一张统计卡。

分段不是永久上限。当某一类增长到需要搜索、筛选或排序时，再把它升级成独立页面；到那时，分段控件只是入口，不是容器。

成就从主页移走：它不是“我”的一个面向，而是奖励记录。放到工具栏的勋章入口，保持可达，不占主页层级。连续阅读/思考天数直接删除：连续不是普遍行为，把天数放在主页等于把“坚持”当成默认价值，断签会像失败；它也帮不上读、想、回看中的任何一步。如果成就系统仍使用连续数据，也不在主页强调。

## 我的（新版）

- 大标题下是系统分段控件：看法 3 / 问题 2 / 记忆 3；标签 13/600，控件高 34，固定在内容上方。
- 选中一类后只显示这一类，放在一个 `SurfaceGroup` 里；行内边距 16，行间 1px 分隔。
- 看法与问题：标题 17/600，摘要 15/400，元信息 13/400；会进入详情的行才有小箭头。
- 记忆：内容 15/400，元信息 13/400，展开箭头；点开展开来源、准确/不准确/修改/忘记，操作沿用现有按钮，不新增组件。
- 空类型：保留分段控件，列表里只放一行 15pt 辅助文字；不画空卡片，不改变页面高度。
- 工具栏：勋章（成就）+ 设置；没有清除记忆的垃圾桶。
- 页边距 16；没有统计卡、没有连续天数、没有成就分区。

SwiftUI 落点：`VStack` 里放 `Picker("", selection:)` + `.pickerStyle(.segmented)`，下面是 `ScrollView`；切换选择只换列表数据，控件位置不变。行继续用 `ContentRow`，容器继续用 `SurfaceGroup` 或 `List(.insetGrouped)` 的一个 section。计数放在段标签里，不放在列表底部，避免出现/消失时推动页面。

## 想法

保留纯时间线，不加分区卡片：月份标题已经完成分组，再加一层容器是重复实体。

- 月标题 20/600，尾部条数 13；页边距 16。
- `ContentRow` 的摘要变体：书名 13/600 + 日期 13/400；摘要 17/600，最多两行；行间 1px 分隔，无卡片边框与小箭头。
- 搜索、分组菜单、设置入口不变。

## 阅读

- 正文 20pt、行高 1.85（37pt），页边距 24，段间距 24；底部留 24pt。
- 章节标题 28/600 宋体，章节标签 13/600 无衬线；顶栏书名 17/600，章节 13。
- 引文是 `QuoteBlock`：18/1.8，左缩进 16，2px 左侧细线；重点句保留一处 32% 黄色高亮。
- 顶栏：返回、书名/章节、搜索、aA；底栏：2pt 进度线、目录、标注、62%、读到这里；图标 44pt 触达，无圆形底板。
- 样张是章节开页；真实分页由 Readium 决定。

## 组件库

六个组件 + 一个系统控件。每个组件至少在两处使用，或承担唯一的阅读语义。

| 组件 | 使用位置 | 规格 |
| --- | --- | --- |
| SectionHeader | 想法 | 20/600，尾部计数 13；上 32 / 下 10 |
| SurfaceGroup | 我的 | 每个列表一个白色容器；圆角 12；行内边距 16；1px 分隔 |
| ContentRow | 想法、我的 | 标题 17/600；可选摘要 15；可选元信息 13；内边距 16；可选小箭头 |
| ReaderChrome | 阅读 | 顶栏 56；底栏 56 + 安全区；材质背景；44pt 触达 |
| QuoteBlock | 阅读 | 18/1.8；左缩进 16；2px 左侧细线 |
| Highlight | 阅读 | 黄色 32% 透明；圆角 2 |

系统控件：`Picker(.segmented)` 承担“我的”的三类切换，不另造分段组件。没有统计卡、没有徽章胶囊、没有单行卡片、没有“查看全部”底部按钮。

## 状态与边界

- 分段切换：控件高度和位置不变；只替换下方列表；空类型用一行文字。
- 计数：在段标签里，固定宽度；不使用内容底部的动态按钮。
- 成就：移入工具栏入口；入口后的列表沿用现有成就数据，本轮不重画。
- 未覆盖：补写想法 Sheet、设置、首启、想法/看法详情、标注菜单。
- 已在 iPhone 17 Pro 模拟器构建、安装并验证；`swift test` 411 个用例通过。
