# ElsePage 用户旅程分析

2026-11-15。对象与证据口径同 [UI/UX 启发式评估](01-ux-audit.md)：当前 `ui/ux-modernization` 构建、iPhone 17 Pro（iOS 26.5）模拟器、1 本书、0 条 Reflection、0 条 Brain、未配置 Provider。首启与真实 AI 成功路径引用上一轮运行记录与当前源码，未在本次清空模拟器重走。本文保留评估时点的旅程；同日已修复部分问题，状态见 [优先问题清单 §10](01-prioritized-issues.md#10-修复记录2026-11-15)。

每个场景都回答：真实目标、理想路径、当前步骤、可能困惑、反馈缺口、隐藏功能、冗余操作、更简单的路径，并标注证据等级与对应问题 ID。

## 场景 A：新用户首次使用 ElsePage

**真实目标**：在几分钟内理解“这是什么、值不值得用”，并开始读第一本书。

**理想路径**：一句价值说明 → 导入一本自己的书 → 可选配置 AI → 打开书开始读。任何一步都能跳过，且跳过不会导致后面卡死。

**当前路径**（上一轮运行 P01–P05 + 当前源码）：

1. 启动 → 全屏首启，没有欢迎页，直接是“把一本你正在读的书带进来”。
2. 选择 EPUB → Files → 导入成功 → “继续”。
3. “连上你自己的 AI”：选服务商、填模型名、填 API Key → “保存并测试连接”；也可“先跳过，之后在设置中配置”。
4. “从《…》开始第一段阅读” → 打开书或“去书架”。

**可能困惑**：

- OpenAI 预设下“模型”为空，用户必须知道并手填模型 ID；空表单也能点“测试连接”（V，UX-016）。
- 为什么先配置 AI 才能进入下一步？虽然可以跳过，但 AI 被放在阅读之前，与“先读书”的产品主张有一点冲突（H）。
- 首启没有解释“想法 / 看法 / 问题 / 记忆”分别是什么；这些词在后续页面才出现（H，UX-021）。

**反馈缺口**：导入成功有明确文案；测试连接有成功/失败状态；跳过一直可见，这部分做得好。缺的是“模型名从哪来”的就地帮助，以及失败后“去设置”的持续入口。

**隐藏功能**：AI 可以完全跳过，之后在设置里配置；这一点在首启写清楚了。

**冗余操作**：没有明显冗余；三步是必要的。

**更简单的路径**：按服务商给一个默认模型名或候选列表；允许“先读，第一次问 AI 时再配置”；在首启最后一页用一句话定义“想法/看法/问题/记忆”。

**证据**：流程 V（上一轮运行），模型名/校验 V（本次设置页观察），术语困惑 H。

## 场景 B：导入 EPUB 并开始阅读

**真实目标**：把一本无 DRM 的 EPUB 放进书库，并尽快打开它。

**理想路径**：书架上的加号 → 选文件 → 看到导入进度 → 新书出现 → 点开。

**当前路径**：

1. 书架右下玻璃加号（只在书架出现）→ 系统 Files。
2. 选择一本 EPUB → 底部出现“正在导入 EPUB…”胶囊。
3. 导入完成 → 书架刷新；如果这是最新导入，它可能直接占据顶部当前书行。
4. 点当前书行 → 阅读器。

**可能困惑**：

- 加号只在书架；用户在想法/我的时想导入，必须切回书架（V，UX-025）。
- 导入成功后没有 toast/“已添加”反馈；新书突然出现在顶部，用户可能以为它是“上次读的书”，但实际只是最新导入（V，UX-028）。
- 重复导入只弹“这本书已经在书库中”，没有说明是同一文件指纹还是同名书（R）。
- 导入失败弹原始错误文案，没有“重试/换文件”的直接动作（R，UX-023 同类）。

**反馈缺口**：导入中有状态，成功后没有确认；外部“用页外打开”支持存在，但界面没有提示。

**隐藏功能**：系统分享/文件打开可导入；批量导入不支持；取消 Files 没有反馈（通常不需要）。

**冗余操作**：空书架同时有中央“导入 EPUB”按钮和底部加号；对空状态可接受，但两个入口没有分工说明。

**更简单的路径**：导入成功后给一个轻量 toast；新导入的书加“新导入”标记，避免与“继续阅读”混淆；加号可考虑在三个 Tab 都可达，或在当前 Tab 提供导入入口。

**证据**：加号与导入状态 V；导入成功路径上一轮 V；本次未重复导入。

## 场景 C：从书架找到一本曾经阅读的书

**真实目标**：找回几周前读过的书，继续读，或确认读到哪。

**理想路径**：书架能看出哪些书读过、读到多少、最近读过哪本；可以按最近阅读/书名/作者排序；搜索能按书名或作者定位。

**当前路径**：

1. 书架顶部只有一本“当前书”，显示封面、书名、作者；进度为 0 时不显示进度。
2. 其余书在“全部书籍”三列网格里，只显示封面、书名、作者。
3. 没有排序入口；搜索框只匹配书名/作者。
4. 点一本书 → 阅读器。

**可能困惑**：

- 网格里没有任何“读过/未读/进度/最近阅读”线索；书一多，只能靠封面记忆（V，UX-006）。
- 当前书是 `lastOpenedAt ?? importedAt` 的最大值；一本刚导入、从未打开的书可以占据顶部，用户会误以为它是上次读的书（V，UX-028）。
- 当前书标题 `lineLimit(1)`，在 225pt 文本列里被截断；行高 180pt 却有大量空白（V，UX-012）。
- 没有排序菜单；设计文档里提到的排序入口已从当前实现移除（V）。

**反馈缺口**：点书会打开，但没有“继续阅读/第几章/百分比”的确认；进度为 0 时完全没有阅读状态。

**隐藏功能**：排序仍在 `LibraryModel.sortOrder` 中，但 UI 没有消费者；VoiceOver 标签包含阅读时长/划线/进度，视觉用户看不到。

**冗余操作**：当前书从网格中排除，避免重复；搜索时当前书又回到网格。这个逻辑是合理的。

**更简单的路径**：在网格给一条极轻的“读到 X% / 最近读过”元信息，或在“全部书籍”旁保留一个排序/筛选菜单；当前书行允许两行标题，并把补写胶囊与元信息对齐。不需要恢复每格三行小字。

**证据**：V（当前 UI）；多书规模下的实际成本 H，需要真实书库测试。

## 场景 D：沉浸阅读、翻页、调整阅读设置

**真实目标**：不被打断地读，随时能调字号/主题，随时能退出。

**理想路径**：打开书即全屏；轻点显隐控制；控制栏出现时，底部目录/标注/进度/结束都可点；退出语义明确。

**当前路径**：

1. 书架点书 → 阅读器；加载时显示封面占位。
2. 首屏后控制栏自动隐藏；轻点正文再显示。
3. 顶部：返回箭头（实际“读到这里并返回”）、书名/章节、搜索、格式。
4. 底部：目录、标注、读到这里、进度——但被 App 自定义玻璃底栏盖住（V，UX-001）。
5. 搜索/格式打开 Sheet；搜索 Sheet 下方还能看到底栏透出（V，UX-001）。
6. 顶部箭头结束会话并可能弹出反思。

**可能困惑**：

- 为什么读书时底部还有“书架/想法/我的/+”？点 Tab 会离开阅读（V，UX-001）。
- 底部的目录/标注/读到这里看不见也点不到（V，UX-001）。
- 顶部返回箭头看起来是“返回”，实际是“结束会话”；如果用户只是想退出阅读，会被弹反思（V，UX-009）。
- 控制栏出现时，章节标题被顶部 chrome 遮住（V，UX-011）。
- 单页样书无法验证翻页手势与多章目录；本次不评价。

**反馈缺口**：控制栏淡入淡出正常；底部动作被遮挡等于没有反馈；没有“轻点显示控制”的首次提示（常见模式，但新用户可能不知道）。

**隐藏功能**：搜索、格式在顶部；目录/标注在底部（当前不可达）；高亮菜单在正文内。

**冗余操作**：顶部“读到这里并返回”和底部“读到这里”是同一动作；一个可见，一个被盖住。

**更简单的路径**：阅读器内隐藏 shell 底栏；只保留一个清晰的退出/结束动作；底部三个阅读动作始终可达；控制栏出现时给正文顶部留出安全区。

**证据**：V（本次运行）。

## 场景 E：选中文字并高亮、批注

**真实目标**：标记一句重要的话，写一点自己的注释，之后能找回。

**理想路径**：长按选词 → 选区工具 → 点颜色立即高亮，或点笔记进入编辑；已有高亮点一下可换色/删除；删除可撤销。

**当前路径**：

1. 长按正文 → 自定义选区工具：4 个颜色圆点、笔记、问、复制。
2. 点颜色 → 立即创建/更新高亮；点“笔记” → 空笔记预览 → 切“编辑” → 输入，400ms 自动保存。
3. 点已有高亮 → 高亮菜单：4 色 + 删除。
4. 删除 → 底部胶囊“已删除高亮 + 撤销”，约 5 秒。
5. 标注列表从底部“标注”进入（当前被底栏遮挡）。

**可能困惑**：

- 颜色只有圆点，没有可见名称；色觉差异用户依赖 AX 标签（V/R，UX-027 同类）。
- 笔记 Sheet 头部同时有“笔记 / 第 N 条 / 追加 / 预览·编辑 / 完成”，在窄屏和大字号下拥挤（R，UX-019 同类）。
- 自动保存没有“保存”按钮，用户可能不确定是否已保存；但“完成”与实时预览能建立信心（H）。
- 底部“标注”入口被盖住，用户只能从正文点高亮，无法查看全书标注列表（V，UX-001）。

**反馈缺口**：高亮立即出现；删除有撤销；复制有胶囊；重叠有解释。整体反馈是全书最好的部分之一。

**隐藏功能**：同范围多条笔记通过“第 N 条”切换；“追加”只在已有笔记时出现；独立下划线可点开笔记。

**冗余操作**：高亮菜单的 4 色和选区工具的 4 色重复，但语境不同，可以接受。

**更简单的路径**：先修复底栏遮挡；笔记 Sheet 头部把“追加/第 N 条”收进一个菜单，给“完成”留出主位；颜色圆点保留，AX 标签已足够。

**证据**：高亮菜单 V；笔记 Sheet 源码 R；上一轮运行 P14–P16 有高亮/空笔记证据。

## 场景 F：阅读中产生问题并请求 AI 回应

**真实目标**：在不离开阅读上下文的情况下，问清楚一段话，并保留追问。

**理想路径**：选中 → 问 → 看到原文卡片 → 解释或输入问题 → 回答与来源 → 追问 / 存为笔记 / 关闭。未配置时能就地配置。

**当前路径**：

1. 选中文字 → “问” → Help Sheet（medium detent）。
2. 顶部“问 AI” + 章节；原文卡片；空态“解释这段”或输入框。
3. 发送 → “正在理解这句话和已读上下文…” → 回答；来源列表；复制 / 存为笔记；可追问。
4. 点引用 → Sheet 缩到 184pt，露出正文并跳转。
5. 左上 X → `discard()` 并关闭，线程丢弃；Sheet 禁止下滑。
6. 未配置 Provider → 错误文字 + 重试；没有“去设置”。

**可能困惑**：

- 未配置时仍可点“问”，然后得到“还没有配置可用的模型服务”，但没有下一步（R，UX-007）。
- X 同时是“关闭”和“丢弃”，没有确认；用户可能以为线程会保留（R，UX-018）。
- Sheet 显示拖拽指示条，却不能下滑关闭，手势与外观矛盾（R，UX-018）。
- 等待回答时没有 Stop，只能等或丢弃（R，UX-017）。
- 提问前没有说明“只用你读到的内容”，防剧透边界不可预判（R，UX-014）。

**反馈缺口**：准备/回答/失败状态清楚；保存笔记有成功提示；没有 Stop；没有配置入口。

**隐藏功能**：默认问题“解释这段”；回答后的来源列表与上下文披露在底部；关闭即丢弃是产品选择，但界面没有把这个选择说透。

**冗余操作**：默认问题 + 输入框是互补的；来源列表与上标引用重复但服务不同任务。

**更简单的路径**：未配置时把“问”变成“配置 AI 后可用”，或在错误里给“去设置”；X 在有对话时确认一次；去掉拖拽指示条；加入 Stop。

**证据**：R（当前无 Provider）；上一轮 P12/P13 观察到 idle 与未配置错误。

## 场景 G：检查 AI 引用并返回原文

**真实目标**：验证 AI 的说法，看到它依据的原文，然后回到回答。

**理想路径**：点 [1] → 看到来源摘要 → 回到原文/旧记录 → 回到回答，位置不丢。

**当前路径**：

1. 回答中的 `[1]` 上标或底部来源列表。
2. 点来源 → Help Sheet 缩到 184pt；书籍证据有 locator → 跳原文，底部胶囊“已回到原文”。
3. 旧反思证据 `locator: nil` → 同样缩 Sheet，但 `jumpToCitation` 直接 return，什么都不发生（R，UX-013）。
4. 想回到回答：把 Sheet 再拉大；没有“回到回答”按钮。

**可能困惑**：

- 点“过去 · 你的想法”后 Sheet 缩小，却没有跳转，也没有解释；用户会以为功能坏了（R，UX-013）。
- Sheet 缩小看起来像关闭；没有明显的“回答还在”的提示（R）。
- 旧反思没有 locator 是数据层事实，但界面把它渲染成可点按钮，承诺了不存在的动作（R）。

**反馈缺口**：书籍证据有“已回到原文”胶囊；过去反思没有任何反馈；没有“回到回答”。

**隐藏功能**：来源列表只在有 citations 时出现；对话详情里的“依据” DisclosureGroup 是另一套入口。

**冗余操作**：上标与来源列表都指向同一证据，但一个用于行内、一个用于总览，合理。

**更简单的路径**：过去反思不要伪装成可跳转；点开一个只读的来源卡（原文 + 书名 + 时间），或标注“无法定位到原文”；给“回到回答”一个明确动作。

**证据**：R（源码 + 数据模型）；上次运行未配置 Provider，未看到成功引用。

## 场景 H：回顾过去的思考或阅读记录

**真实目标**：回看自己写过什么、AI 说过什么，继续讨论或整理。

**理想路径**：想法 Tab 按时间/书浏览 → 搜索 → 打开详情 → 看原文/回应/依据 → 继续追问或编辑。

**当前路径**：

1. 想法 Tab：标题、搜索、更多菜单（按时间/按书、设置）。
2. 空态：“还没有留下记录”；有数据时按月/书分组，行摘要 17/600 + 元信息 13。
3. 点记录 → 自绘返回 + 对话详情；原文、AI 消息、依据、追问输入。
4. 我的 Tab：看法/问题/记忆分段；看法/问题详情可编辑、存档为记忆、标记已解决；记忆可展开来源、准确/不准确/修改/忘记。
5. 删除记录：长按消息 → 上下文菜单；删除整条有确认。

**可能困惑**：

- “想法”Tab 是阅读记录，“我的 → 看法”才是 Brain Thought；用户不知道“想法”和“看法”的边界（H，UX-021）。
- 空态没有“去书架读一本”的 CTA，只有说明文字；新用户可能停在这里（V，UX-021 同类）。
- 记录详情返回是左上浮动圆形 chevron，和根页面标题行不是一套；底部玻璃栏仍在（V，UX-026）。
- 删除入口藏在长按菜单，详情页没有可见的“更多/删除”（R，UX-024）。
- 没有 Journal/记录编辑入口；PRD 的编辑能力在服务层存在但 UI 不可达（R）。
- “继续想想”可见但无反应（R，UX-004）。
- 记忆“忘记”立即硬删除，无确认/撤销（R，UX-008）。

**反馈缺口**：详情有加载/错误/空态；删除有确认；记忆操作后 reload。缺的是“继续想想”的反馈和“想法/看法”的定义。

**隐藏功能**：分组菜单、设置菜单都在“更多”；记录编辑不存在；Journal “这次留下”只在数据存在时显示。

**冗余操作**：想法详情复用了反思对话，避免两套 UI，这是优点。

**更简单的路径**：给空态一个“去书架”按钮；把记录删除/编辑放到详情右上“更多”；用一句微文案定义“想法（阅读记录）/看法（长期形成的观点）”；接通或移除“继续想想”。

**证据**：空态 V；有数据状态 R（模拟器无 Reflection/Brain）；上一轮未触达正式 F01/F02/T01。

## 场景 I：加载失败、离线和异常状态

**真实目标**：知道发生了什么，能重试，且已经写下的内容不丢。

**理想路径**：本地内容永远可读；网络失败有明确状态与重试；草稿/原文先落库；破坏性操作可撤销。

**当前路径**：

1. 启动失败 → 静态“无法打开本地书库”，无重试（R，UX-023）。
2. 导入失败 → “导入失败” Alert + 原始错误；重复 → “这本书已经在书库中”。
3. 反思保存：原文先落库；失败回编辑；AI 首次回应失败有 notice/重试。
4. 追问：pending 气泡；失败可“重新发送”；`.sending` 显示“已发送”（R，UX-017）。
5. Reader Help：失败文字 + “重试”；未配置 Provider 无设置入口（R，UX-007）。
6. 索引/Embedding 失败：设置页显示状态，需要手动刷新；不阻塞阅读。
7. 补写想法：关闭/下滑即永久 dismissal，草稿不保存（V/R，UX-002）。

**可能困惑**：

- 哪些内容已经保存在本机、哪些还在等网络？界面没有统一的“已保存/待同步”模型。
- 启动失败没有修复按钮；用户只能杀 App 重开（R）。
- AI 错误后要离开阅读器、去设置；路径太长（R）。
- “已发送”在发送中提前出现，用户以为已经成功（R）。
- 反思的“今天先不了”看起来是可逆的，实际不可逆（V）。

**反馈缺口**：局部反馈很多（Alert、notice、胶囊、重试），但缺少跨页面的“保存状态”与“可恢复入口”；破坏性操作没有统一撤销。

**隐藏功能**：追问失败后的“重新发送”；缺失首次回应时的“让页外回应”；索引任务会在启动时恢复（不面向用户展示）。

**冗余操作**：多种错误表面（Alert、inline Label、notice、toast）并存，用户需要重新学习每种的含义。

**更简单的路径**：统一三类状态：本地已保存 / 等待网络 / 需要操作；给 AI 错误一个“去设置”；给启动失败一个重试；给补写一个持久草稿与明确“放弃这次”确认。

**证据**：R（源码与上一轮 P13）；本次未制造网络/启动失败。

## 跨场景结论

| 反复出现的问题 | 出现的场景 | 影响 |
| --- | --- | --- |
| 自定义底栏越过阅读器边界 | D、F、G、H | 遮挡控件、破坏沉浸、同一阅读器两种 chrome |
| 放弃/删除的后果没有说清 | A、C、H、I | 永久 dismissal、删书连带反思、忘记记忆不可撤销 |
| 书库不回答“读到哪/哪本读过” | B、C | 多书时找回旧书成本高；新导入与上次阅读混淆 |
| 差异化能力有入口无闭环 | F、G、H | 继续想想死按钮、过去反思死引用、AI 未配置死路 |
| 大字号破版 | A–I 全部 | 搜索与当前书行不可读，属于阻断性无障碍问题 |
| 术语与状态模型不统一 | A、C、H、I | 想法/看法、已发送/发送中、本地/网络 |

**最值得先修的不是视觉，而是边界**：shell 与阅读器的边界、放弃与删除的边界、书库“当前书”与“其他书”的边界。三条边界修好后，现有视觉语言才真正成立。
