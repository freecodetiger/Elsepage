# 页外「想法」页 UI 重构 Spec

**状态：** Locked  
**日期：** 2026-09-14  
**范围：** 想法页信息架构、卡片、概要生成、自动 AI 回应、视觉层级与验收  
**原型：** `docs/prototypes/thoughts-redesign.html`  
**上位规范：** `docs/UI_LANGUAGE_AND_IA_SPEC.md`

---

## 1. 目标

把「想法」页从“记录列表 + 多种状态 + 管理操作”收敛成一条安静的阅读主线：

1. 用户扫一眼就知道每条记录大致讲了什么。
2. 用户点开一条记录后，能看到自己的原话、AI 回应和必要依据。
3. 页面默认不展示状态、关联数量和讨论次数。
4. 所有 Reflection 默认获得 AI 回应，不再要求用户手动请求。
5. 概要自动生成、永久固定，成为卡片最稳定的识别信息。
6. 保留现有玻璃材质与 iOS 原生触感，不把应用壳层改成网页式纯平面。
7. 所有日期和系统生成文案保持中文语境。

---

## 2. 非目标

本次不做：

- 不重命名 Reflection、Thought、Question、Memory 的领域模型。
- 不修改阅读器正文排版和阅读主题。
- 不把整个应用改成无材质平面风。
- 不做完整国际化；首发仍以简体中文为主。
- 不把「想法」页做成 Knowledge Graph、数据看板或完整 Journal 管理器。

---

## 3. 锁定决策

### 3.1 页面级

- 一级导航仍为：`今天 / 书架 / 想法 / 我的`。
- 「想法」页不再包含 `档案` 入口。
- 用户界面不再使用“档案”作为对象名。
- 不再显示 `记录 / 档案` 分段控件。
- 不再显示 `全部 / 有回应 / 有关联` 筛选胶囊。
- 搜索通过下拉进入，不常驻为搜索框。
- 分组与设置收进一个工具栏菜单，默认不占据内容区。
- 页面默认只有一个主信息流。

### 3.2 卡片级

折叠态只显示：

1. 书名。
2. 中文日期。
3. 自动生成的概要。
4. 一个不喧宾夺主的展开指示。

折叠态不显示：

- “有回应”
- “请 AI 回应”
- “有关联”
- “N 次讨论”
- 高亮数、引用数、记忆变化数
- 编辑、删除或其他管理按钮

所有卡片使用相同的静止样式。第一张卡片不得拥有持久高亮边框或选中背景。

### 3.3 详情级

点击卡片进入这条记录的“世界”，顺序固定为：

1. 书名与中文日期。
2. `概要`：圆形摘要标记 + 自动生成的短句。
3. `我的原话`。
4. `AI 回应`。
5. `这次留下`，仅在存在结构化内容时显示。
6. 对话输入区：只在详情页底部出现。
7. `依据`：详情页末尾的普通内容区，包含本次上下文、关联记录和回到原文。

不得把高亮、引用和记忆变化另藏进二级展开。

### 3.4 视觉级

- 玻璃材质保留，但只用于导航栏、Tab、工具栏、菜单、Sheet、选择器和浮层。
- 正文卡片和长文本阅读表面使用中性实色，避免玻璃模糊文字。
- 视觉温度来自排版、留白、层级、材质和动效，不来自绿色品牌色。
- 品牌色、交互色和状态色继续保持语义分离。
- 绿色只表达成功状态，红色只表达危险、失败和录音中。

## 4. 对象与语言

### 4.1 用户可见对象

| 对象 | 用户名称 | 含义 |
|---|---|---|
| Reflection | 阅读记录 | 用户在一个阅读节点留下的原始表达 |
| Summary | 概要 | 从第一次记录和第一次 AI 回应生成的固定短句 |
| Agent response | AI 回应 | 页外针对记录进行的第一次回复 |
| Structured leftovers | 这次留下 | 从本次记录中形成的看法、问题和相关原文 |
| Thought | 看法 | 跨多次记录逐渐形成的长期观点 |
| Question | 问题 | 仍未解决、值得继续追踪的问题 |
| Memory | 记忆 | 用户允许页外长期依赖的信息 |

### 4.2 删除的用户词

从「想法」页主界面删除：

- `档案`
- `Journal`
- `有回应`
- `请 AI 回应`
- `连接过去`
- `N 次讨论`
- `RAG`
- `Embedding`
- `Reranker`
- `Provider`
- `Reflection`

上述词可以继续存在于内部类型、数据库、高级设置、诊断页面和开发文档中。

### 4.3 术语边界

```text
概要
= 一条记录的固定一分钟级识别信息

我的原话
= 用户原始表达

AI 回应
= 页外对这条记录的第一次回应

这次留下
= 从这条记录整理出的结构化内容

我的
= 跨多条记录形成的长期看法、问题和记忆
```

## 5. 页面信息架构

### 5.1 顶部结构

```text
想法
[工具栏：分组与设置]
```

- 导航标题：`想法`
- 默认大标题，向下滚动时按系统行为收为 inline 标题。
- 工具栏仅保留一个菜单入口。
- 菜单内容：
  - 按时间
  - 按书籍
  - 设置

搜索通过系统 searchable 或下拉手势进入，不显示常驻搜索框。

### 5.2 分组标题

- 按时间：`2026年9月`
- 按书籍：`《书名》`
- 右侧显示轻量数量：`3 条记录`

数量和月份不得使用胶囊、彩色标签或按钮样式。

### 5.3 自适应布局

- Compact width（当前 iPhone）：列表使用 `NavigationStack`，点击卡片 push 到独立详情页。
- Regular width（未来 iPad / 大屏）：列表与详情使用 `NavigationSplitView`，左侧保持记录历史，右侧呈现当前记录世界。
- 任何尺寸下都不得退回“卡片原地展开后再点一次”的层级。
- 对话输入区只属于详情页，不常驻列表。

### 5.3 空状态

没有记录时：

```text
还没有留下记录

结束一次阅读后，写下一点真正留下来的东西。
```

没有搜索结果时使用系统搜索空状态。

不得因为缺少 AI 回应而出现额外操作入口。

## 6. 折叠卡片 Spec

### 6.1 结构

```text
《书名》 · 9月14日

概要短句，最多两行。

                                        ›
```

### 6.2 视觉

- 卡片是整块唯一点击目标。
- 圆角：`20pt`。
- 边距：建议水平 `16pt`，上方 `16pt`，下方 `15pt`。
- 所有卡片使用相同边框。
- 默认不使用持久阴影；按压态可以轻微缩放或改变边框。
- 卡片背景：中性 `surface`。
- 页面背景：中性 `background`。
- 卡片与页面之间必须有可感知的表面差，不得只靠一条极浅边框区分。
- 不使用玻璃材质作为卡片背景。

### 6.3 文字层级

| 元素 | 字体 | 颜色 |
|---|---|---|
| 书名与日期 | `.caption` / 12pt | secondary |
| 概要 | `.body.weight(.semibold)` / 16pt | primary |
| 展开指示 | caption symbol | tertiary |

要求：

- 概要用摘要文本，不使用原文前 3 行。
- 概要最多 2 行，超出时系统截断。
- 书名和日期可同一行，也可在窄屏下换行。
- 书名的视觉权重大于日期，但弱于概要。

### 6.4 点击与导航

- 点击整张卡片进入独立详情路由。
- 卡片不原地展开，也不显示 inline expanded content。
- 不显示持久 selected 边框；卡片在按压时可以出现短暂状态。
- 详情页提供返回入口，使用系统导航返回优先。
- 不显示卡片级 context menu，删除等操作进入详情页菜单。

## 7. 记录详情 Spec

### 7.1 顶部

记录详情页不显示厚大的系统标题栏。

```text
‹
概要
《书名》 · 9月14日
```

- 隐藏 `NavigationBar`，最大化正文阅读面积。
- 左上角保留一个 44pt 玻璃悬浮返回按钮。
- 不显示“阅读记录”大标题。
- 详情正文顶部留出悬浮按钮的避让空间。
- 编辑、删除、回到原文等低频操作进入详情页内的菜单或依据区。

### 7.2 概要区

```text
● 概    自由让人不安，是因为结果必须由自己承担。
```

要求：

- 圆形标记包含字符 `概`。
- 圆形标记建议 `36pt × 36pt`。
- 概要正文建议 19–20pt，最多两行。
- 概要只读，不提供编辑、重写、刷新操作。
- 概要生成后永久固定，即使模型、Provider 或 prompt 版本变化，也不自动重写。

### 7.3 我的原话

- 标签：`我的原话`
- 正文：用户原始 Reflection，不显示 AI 改写版为默认。
- 如果存在润色版，润色仍是独立展示版本，不改变 originalText 的事实地位。
- 正文最多铺满，不设置人为行数限制。

### 7.4 AI 回应

- 标签：`AI 回应`
- 使用次级表面卡片或内嵌区域。
- 次级表面不得使用玻璃。
- 默认完整展示第一次 AI 回应。
- 不显示“有回应”。

### 7.5 这次留下

仅当存在结构化内容时显示：

```text
这次留下

看法
...

问题
...

相关原文
...
```

规则：

- 没有结构化内容时，整个区域不显示。
- 不出现“档案”标题。
- 不默认展开全部高亮、引用、记忆变化。
- 结构化内容如果用户已经编辑，展示用户版本。
- 结构化内容不覆盖我的原话。

### 7.6 对话与输入

- 详情页底部提供对话输入区域，不常驻列表页。
- 没有历史追问时也允许直接开始对话。
- 不再显示“继续对话”二级按钮。
- 对话消息按时间顺序直接接在 AI 回应之后。
- 输入框只在详情页存在，离开详情后自然消失。

### 7.7 依据

- 依据是详情页的普通内容区，不作为二级展开入口。
- 包含本次使用的上下文、关联的过去记录、相关高亮与引用、回到原文。
- 调试信息不展示给普通用户。

## 8. 概要生成与生命周期

### 8.1 生成时机

概要必须在以下两个数据都存在后生成：

1. 用户第一次提交的 Reflection。
2. 该 Reflection 的第一次 Agent response。

不得在 Reflection 保存前生成。  
不得等待用户手动点击任何按钮。

### 8.2 输入

概要生成输入固定为：

- `reflection.originalText`
- 第一次 agent response 的 `content`

不得把未来的追问、编辑后的结构化看法或后续对话混入概要输入。

### 8.3 输出要求

- 只输出一句中文概要。
- 目标长度：12–24 个中文字符。
- 硬上限：36 个中文字符。
- 尽可能陈述用户这次留下的核心意思。
- 不得添加用户没有表达、AI 回应也未支持的新观点。
- 不得使用：
  - “用户认为”
  - “这段记录说明了”
  - “这篇文章讨论了”
  - Markdown
  - 编号
  - 引号包裹整句
  - 面向用户的问答或鼓励语
- 应像用户自己留下的一句话，而不是模型报告。

示例：

```text
自由让人不安，是因为结果必须由自己承担。
地方政府本身就在塑造市场。
理解一个人，并不等于赞同他。
```

### 8.4 不可变性

概要一旦成功写入：

- 不可由用户编辑。
- 不可由后续模型自动重写。
- 不因 Provider 或模型变化重新生成。
- 不因 AI 继续回复或用户追问而更新。
- 只有删除 Reflection 时，概要随之下级删除。

不可变性的目的不是增加约束，而是让这张卡长期稳定。

### 8.5 失败与缺失

用户的 Reflection 保存永远不能被概要生成失败阻塞。

正常路径：

```text
保存 Reflection
→ 自动请求第一次 AI 回应
→ 保存回应
→ 生成概要
→ 原子写入概要
→ 刷新卡片
```

失败路径：

- AI 回应失败：后台按既有重试策略继续，不显示“请 AI 回应”。
- 概要生成失败：卡片临时使用用户原文中第一个完整句或截断后的本地 fallback。
- fallback 不是概要，不写入概要表。
- 概要成功后可静默替换 fallback。
- fallback 期间不向列表暴露错误、重试或模型状态。

## 9. 自动 AI 回应约束

### 9.1 产品不变量

每条成功保存的 Reflection 都必须自动进入“等待第一次 AI 回应”的流程。

用户不需要：

- 点击“请 AI 回应”。
- 进入设置确认是否回应。
- 从列表手动触发。

### 9.2 失败语义

- 离线时先保存本地 Reflection。
- 网络恢复后自动继续。
- 模型失败时由运行时重试，不丢失用户原文。
- 列表不显示失败状态。
- 详情页可以显示一条安静的异常说明，但不提供卡片级重试按钮。
- 如果长期失败，系统设置或诊断页可以提供恢复入口。

### 9.3 历史数据

已存在但没有 AI 回应的 Reflection：

- 首次升级后进入后台补齐队列。
- 仅在 Provider 可用时执行。
- 补齐成功后生成概要。
- UI 不要求用户逐条处理。
- 补齐失败不影响历史原文和阅读记录显示。

## 10. 数据模型与持久化

### 10.1 ReflectionSummary

建议新增不可变领域对象：

```text
ReflectionSummary
- reflectionID
- text
- sourceMessageID
- promptVersion
- createdAt
```

约束：

- 一个 Reflection 最多一条概要。
- `reflectionID` 唯一。
- `text` 非空。
- `sourceMessageID` 指向第一次 Agent response。
- 删除 Reflection 时级联删除概要。

### 10.2 Repository 语义

建议接口：

```text
summary(for reflectionID) -> ReflectionSummary?
saveIfAbsent(summary) -> ReflectionSummary
```

禁止：

- 覆盖已存在概要。
- 用同一 Reflection 创建第二条概要。
- 在 UI 层直接修改概要。

### 10.3 生成任务

概要任务必须幂等：

- 多个生成任务同时到达时，只允许第一条成功写入。
- 已有概要时直接返回，不再次调用模型。
- 任务失败不改变 Reflection 和已有消息。
- 任务不阻塞 Reflection 保存、阅读页关闭或列表刷新。

## 11. 视觉系统

### 11.1 玻璃边界

使用玻璃：

- 顶部导航栏。
- 底部 Tab。
- 工具栏菜单。
- Reader Help 等浮层。
- Sheet、选择器和临时弹层。

不使用玻璃：

- 想法卡片。
- AI 回应正文。
- 长文本阅读区域。
- 数据列表的背景。

### 11.2 表面层级

目标色值：

| Token | Light | Dark |
|---|---|---|
| page background | `#F2F2F2` | `#0B0B0B` |
| primary surface | `#FFFFFF` | `#181818` |
| secondary surface | `#F7F7F7` | `#222222` |
| border | `#D4D4D4` | `#343434` |
| content primary | `#111111` | `#F4F4F4` |
| content secondary | `#666666` | `#A6A6A6` |
| content tertiary | `#6E6E6E` | `#8A8A8A` |

要求：

- `page background` 与 `primary surface` 必须有可感知差异。
- 边框属于结构信号，不依赖颜色表达唯一语义。
- 暗色模式使用炭黑，不使用橄榄绿黑。
- 所有正文和交互色继续满足 WCAG AA 4.5:1。

### 11.3 字体

- App UI 统一使用系统无衬线字体。
- 书名和阅读内容可以使用衬线字体。
- 概要不使用夸张的大标题字号。
- 卡片概要建议 16pt。
- 展开概要建议 19–20pt。
- 正文建议 15–17pt。
- 元数据建议 11–12pt。
- 不通过 `.caption2` 强行塞入更多信息。

### 11.4 圆形概要标记

- 圆形 `概` 标记只在记录详情页出现。
- 它是视觉锚点，不是按钮。
- 不提供点击行为。
- 不在折叠列表的每张卡上重复。

---

## 12. 中文与日期

### 12.1 语言

- 主流程全部使用自然中文。
- `九月`、`Sep`、`September` 不作为用户可见月份。
- 英文技术原文只出现在高级设置和诊断中。

### 12.2 日期格式

统一输出：

- 月份分组：`2026年9月`
- 卡片日期：`9月14日`
- 展开日期：`9月14日`
- 详情时间：`2026年9月14日 23:10`

要求：

- 日期格式集中管理，不散落调用系统默认格式。
- 应用 Chinese locale 固定为 `zh-Hans` 或使用明确的中文日期格式。
- 设备系统语言变化不得让主界面出现英文月份。
- 单元测试必须覆盖 `September`、`Sep` 不出现。

---

## 13. 交互与无障碍

- 折叠卡片整块点击，最小点击高度不低于 44pt。
- 卡片使用一个 combined accessibility element。
- VoiceOver 顺序：书名、日期、概要、展开提示。
- 不把状态和讨论次数读入折叠卡片。
- 玻璃层不能降低文字对比度。
- Dynamic Type 下，卡片概要最多两行，超出后允许卡片增高而不是缩字。
- 详情页的所有操作保持 44pt 最小触点。
- Reduce Motion 下取消移动和缩放动画。

## 14. 从当前实现迁移

### 14.1 删除

- `ThoughtsArchiveFilter.hasAgentResponse` 的用户界面入口。
- 记录卡片中的“请 AI 回应”按钮。
- 记录卡片中的“有回应”、“连接过去”、“N 次讨论”状态。
- `记录 / 档案` 分段控件。
- 档案卡片和档案空状态。

### 14.2 保留

- Journal 数据模型和持久化。
- 结构化看法、问题、引用、记忆变化。
- `这次留下` 的数据来源。
- 我的页跨记录使用这些数据。
- 导出、删除和隐私能力。

## 15. 验收标准

### 15.1 页面

- 主导航仍为 `今天 / 书架 / 想法 / 我的`。
- 想法页不存在“档案”入口。
- 想法页不存在“有回应”筛选。
- 折叠卡片只显示书名、中文日期和概要。
- 点击卡片 push 到独立详情页，不再原地展开。
- 所有卡片静止态样式一致。
- 页面默认不出现管理型按钮。

### 15.2 概要

- 第一次 Reflection 和第一次 AI 回应保存后自动生成概要。
- 概要长度不超过 36 个中文字符。
- 概要生成后不会因重新打开页面、模型变化或后续对话而改变。
- 删除 Reflection 时概要一并删除。
- 概要失败不会影响 Reflection 保存。
- 历史记录可以在后台逐步补齐概要。

### 15.3 AI 回应

- 新的 Reflection 不需要手动请求 AI 回应。
- UI 中不存在“请 AI 回应”。
- 离线或失败不会丢失 Reflection。
- 网络恢复后可自动补齐第一次回应和概要。

### 15.4 视觉

- 导航、Tab、菜单和 Sheet 保留玻璃材质。
- 卡片和 AI 回应正文使用中性实色表面。
- 页面背景、主表面和次级表面存在清晰层级。
- 中文日期在所有支持的设备语言下保持中文。
- 深色模式不使用绿色或橄榄色底。

### 15.5 测试

必须增加或更新：

- 概要生成输入与输出测试。
- 概要长度和禁止内容测试。
- 概要不可覆盖测试。
- 概要与 Reflection 级联删除测试。
- 无回应历史补齐测试。
- 中文日期格式化测试。
- 卡片不显示旧状态和手动回应入口的 UI 测试或快照测试。
- 玻璃使用范围和无障碍对比度测试。
