# 交互延迟手测（2026-09-12）

安装本次 DEBUG 构建，进入设置 → 路由诊断。新增「复制性能报告」「清空采样，开始新一轮」「刷新采样」。报告保留最近 200 条内存事件，不含正文、输入内容或凭据；退出 App 即清。

## 测试步骤

1. 冷启动后先测第一次键盘唤起，再打开诊断页复制报告，标注「冷启动键盘」及体感。
2. 清空采样，回会话，收起再唤起键盘三次。每次等动画结束，复制报告，标注「重复键盘」。
3. 清空采样，在已完成的长回复中长按未选中的正文，等选区出现，再拖动手柄。立即复制报告，注明延迟发生于长按启动还是拖动。
4. 清空采样，切换另一段正文重复。可再单独测试流式生成中的长按。

每组测试后尽快复制，避免后续事件挤出最早记录。报告文本直接发回即可，可附截图/录屏。

## 解释边界

- 第二轮新增：输入框触摸→编辑代理回调、becomeFirstResponder 调用耗时、键盘 frame 通知参数、滚动祖先的 delaysContentTouches 和长按识别器公开配置。保留系统手势行为。
- 每次触摸/获取输入焦点启动最多 30 次、间隔 50ms 的主队列探针，记录超出间隔的调度延迟；新交互替换旧探针，清空报告时取消，App 非活跃时停止。它是线程调度信号，不是精确 CPU 或掉帧测量。
- 输入框触摸只覆盖会话的 UIKit 输入组件；若 UIKit 在 touchesBegan 递送前已开始编辑，则该样本可能缺失。键盘 frame 的 will/did 仍是通知，不是逐帧实测。

- 编辑开始→WillShow 与 WillShow→DidShow 是通知之间的墙钟时间，另列系统声明的动画时长；不能相减后直接认定系统或 App CPU 开销。尚未覆盖点击输入框→开始编辑。
- selection.touchDelivery 是触摸时间戳到 touchesBegan 递送的时间；selectionStart 是该触摸到首次非空选区回调，包含系统长按识别时间，不表示选区已上屏。
- 已有选区的手柄拖动不计入启动样本；文本被替换会作废待匹配触摸；超过 3 秒的选区回调标为 expired。若系统未递送 touchesBegan，可能没有选区样本，不表示延迟为零。
- textLayout 和 textUpdate 是单次布局、更新耗时，textMeasure 为原测量指标。超过 8ms 的调用写入事件线；不要把嵌套计时简单相加。
- 本次修正 UIViewRepresentable 的释放计数回调，旧版常驻文本视图数量可能偏高，不宜直接比较。
